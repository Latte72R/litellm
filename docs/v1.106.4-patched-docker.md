# Docker: v1.106.4-patched

This branch combines draft PRs #1 (weighted-least-busy), #2
(capacity-aware session affinity), and #3 (retrying failed pins and
successful failover repinning). It is based on official LiteLLM v1.106.4.

It uses the original ghcr.io/berriai/litellm:v1.106.4 image **without a
custom Dockerfile or image build**. The installer creates a stopped
container, copies six patched Python files into its original virtual
environment, and starts it after patching.

## Set router_settings in your existing config.yaml

~~~yaml
router_settings:
  routing_strategy: weighted-least-busy
  redis_url: redis://redis:6379
  optional_pre_call_checks:
    - session_affinity
  session_affinity_capacity_aware: true
  deployment_affinity_ttl_seconds: 14400
  num_retries: 2
  enable_weighted_failover: true
~~~

Keep the existing 28 model deployments and all max_parallel_requests
limits unchanged. Keep your existing compose.yaml (including Postgres
and Redis), with LiteLLM using image ghcr.io/berriai/litellm:v1.106.4.
Do not enable more than one LiteLLM worker: concurrency slots are local
to a Python process.

## Install on your Docker host

Assuming your existing compose.yaml and .env are in /opt/litellm:

~~~bash
git clone --branch v1.106.4-patched --single-branch \
  https://github.com/Latte72R/litellm.git /opt/litellm-patched
sudo env COMPOSE_DIR=/opt/litellm \
  bash /opt/litellm-patched/scripts/apply-patched-docker.sh
~~~

The script starts and waits for healthy postgres + redis, recreates
**only** the stopped LiteLLM container, checks the exact original image
tag and Python package path, copies the patched source files, and then
starts LiteLLM with your **existing** config and compose command. Database
and Redis volumes are not deleted.

The installed package path is
/app/.venv/lib/python3.13/site-packages/litellm, matching the v1.106.4
Docker image.

The six changed modules:
- litellm/router.py
- litellm/router_strategy/least_busy.py
- litellm/router_utils/pre_call_checks/deployment_affinity_check.py
- litellm/caching/affinity_cache.py
- litellm/types/router.py
- litellm/types/litellm_params.py

When pulling updated patches, use git pull --ff-only in the repository
and rerun the installer. **Container recreation removes these changes**:
always rerun the script after docker compose up --force-recreate,
docker compose rm, or a change to the Compose service that recreates it.
An ordinary docker compose restart retains them. To restore unmodified
LiteLLM, recreate the official container without applying this script.

Verify via docker compose logs --tail=100 litellm and:

~~~bash
sudo docker compose exec -T litellm /app/.venv/bin/python -c \
  'from litellm.types.router import RoutingStrategy; print(RoutingStrategy.WEIGHTED_LEAST_BUSY.value)'
~~~

Expected: weighted-least-busy.

## Limitations

This is a convenience/testing branch, **not a production-verified release**.
It is currently based on experimental draft PRs. Targeted Python unit
tests for individual PRs passed, but Docker-based concurrency, acquire-
time slot races, streaming responses, Redis failures, and true success-
only repinning have **not** been validated end-to-end. The capacity
preflight cannot eliminate every possible 429. Only asynchronous
routing behavior has been targeted. Image dependencies stay pinned to
official v1.106.4 and its existing vulnerability findings.
